# Allo-Media (uh!ive)

> Allo-Media, now trading as uh!ive, is a French conversational-voice-AI company
> that transcribes and analyses phone calls in real time and in batch. Its
> platform combines speech-to-text tuned for 8kHz telephony, named-entity
> recognition and redaction, speech analytics (intent, emotion, compliance
> tagging) and call tracking, hosted sovereignly in France. Developers reach it
> through a read-only REST API for processed calls, two WebSocket/MRCP streaming
> APIs (human-to-human and human-to-bot), an SFTP batch ingestion channel, and a
> browser call-tracking script.

## APIs

- [Activate API (REST)](https://docs.allo-media.net/activate-api/rest/): read-only access to processed calls, their transcripts, analytics tags and audio. Base URL `https://activate.uh.live`. Operations: `GET /calls`, `GET /calls/{unique_id}`, `GET /calls/{unique_id}/audio`.
- [Activate API webhook](https://docs.allo-media.net/activate-api/webhook/): HTTP POST notification when a call finishes processing, signed with HMAC-SHA256 in `X-Uhlive-Signature`.
- [Stream API for humans (H2H)](https://docs.allo-media.net/stream-h2h/): real-time transcription of live conversations over WebSocket. `wss://api.uh.live/socket/websocket?vsn=2.0.0&jwt=...` (Phoenix Channels). Protocol V2 current, V1 deprecated.
- [Stream API for voicebots (H2B)](https://docs.allo-media.net/stream-h2b/): real-time recognition for IVR/voicebots over MRCP or WebSocket, with regex grammars.
- [JUpload](https://docs.allo-media.net/jupload/): SFTP batch ingestion of audio plus CSV/JSON/XML metadata, optional GPG encryption.
- [Hermes](https://docs.allo-media.net/hermes/): browser JavaScript for dynamic number insertion and call tracking.
- [Bot Orchestrator](https://docs.allo-media.net/bot-orchestrator/): telephony + speech integration for chatbots.

## Authentication

- [Activate API authentication](https://docs.allo-media.net/activate-api/rest/authentication/): OAuth 2.0 client_credentials against the Keycloak realm token endpoint `https://id.uh.live/realms/uhlive/protocol/openid-connect/token`, then `Authorization: bearer {access_token}`. Token lifetime 60 minutes.
- [Stream API authentication](https://docs.allo-media.net/stream-h2h/protocol/): same grant; the token is passed as the `jwt` query parameter on the WebSocket handshake and is valid 5 minutes.
- No self-service signup. `client_id` / `client_secret` are issued by an account manager. No OAuth scopes are documented.

## Conventions and limits

- Pagination: `limit` (default 50, max 200) and `offset` (max 10000); response carries `count` and `data`.
- Filtering: `timestamp_from`, `timestamp_to`, `qualified_from`, `qualified_to`, `status` (`qualified` / `void`).
- Ordering: `order=timestamp` or `order=qualified`.
- Sparse responses: `exclude=transcript_json,tracking_info,qualification` (any first-level field except `unique_id`).
- Rate limit: 40 requests per IP per rolling 10 seconds, then HTTP 429. No rate-limit or `Retry-After` response headers are published.
- Stream bandwidth limit: 20 kB/second/WebSocket connection.
- Errors: plain HTTP status codes, no RFC 9457. Documented: 400 (bad `exclude` field), 404 (unknown call), 429 (rate limit), 451 (audio deleted under the GDPR retention policy).

## Specs

- No OpenAPI, Swagger, AsyncAPI, GraphQL or Protobuf document is published at a reachable URL. The documentation links a Swagger UI for the pre-v3 API at `https://api.allo-media.net/swagger`, but that host refused all connections from our probe on 2026-08-17, so no machine-readable contract could be retrieved or verified.
- The two event surfaces (webhook, WebSocket) are documented in prose only. The JavaScript SDK's TypeScript enums and interfaces (`DecodingEvent`, `EntityEvent`, `EntitiesRelationEvent`, `WordsDecoded`, `SegmentDecoded`, `SpeakerJoined`, ...) are the nearest thing to a machine-readable event catalogue.
- No MCP server and no A2A agent card. `/.well-known/agent-card.json` and `/.well-known/agent.json` both returned HTTP 404 on uh.live.
